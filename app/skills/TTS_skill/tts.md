# 口播逐句 TTS（tts-synthesizer）

## 1. 目标

把上一个技能 `video-script-splitter` 输出的口播拆分稿，**逐句**调用 TTS 合成音频。

全部句子转换完成后，音频按句序保存为：

```text
output/sucai/1.mp3
output/sucai/2.mp3
output/sucai/3.mp3
output/sucai/4.mp3
...
```

文件名就是句序号，不带前缀；第 `N` 个音频对应拆分稿第 `N` 句。

## 2. 输入

必填：

- `script`：上一个技能输出的口播拆分稿，纯文本，或该 `.txt` 文件的路径。

格式约定：

- 一句一段，句与句之间空一行；
- 允许保留上一技能在逗号后插入的四个空格；
- 允许包含中文、英文、数字和标点。

可选：

| 参数 | 默认值 | 说明 |
|---|---|---|
| `output_dir` | `output/sucai` | 音频输出目录 |
| `fmt` | `mp3` | 音频格式；所有句子必须一致 |
| `voice` | 由 TTS Provider 决定 | 音色 |
| `speed` | `1.0` | 语速 |
| `retry` | `2` | 单句失败重试次数 |

不适用：

- 关键词、提纲、未拆分的长文；
- 背景音乐、音效、声音克隆；
- 字幕、视频剪辑。

## 3. 输出

- 目录：`<项目根>/output/sucai`，即当前项目下的 `D:\pj3_Auto_Upload-main\pj3_Auto_Upload-main\output\sucai`；
- 文件：`1.mp3`、`2.mp3`、`3.mp3`……从 1 开始连续编号，不跳号；
- 第 `N` 个文件必须对应拆分稿第 `N` 句；
- 句子数量必须等于音频数量；
- 默认格式为 `mp3`；如果 Provider 输出 `wav` 或 `opus`，同一次任务内统一格式；
- 目录创建和旧文件清理策略：**本版先不写死，留给后续脚本调整**；执行脚本需要保证目录存在，并能处理同名文件；
- 不额外生成 manifest 文件，顺序由文件名保证；后续视频合成需要更多元数据时再加。

## 4. 执行方式

推荐由 Agent 调用**一个批量工具**，而不是让 Agent 自己逐句调用 TTS。

```python
batch_synthesize_script(
    script: str,
    output_dir: str = "output/sucai",
    fmt: str = "mp3",
    voice: str = "",
    speed: float = 1.0,
    retry: int = 2,
) -> list[str]
```

工具内部负责：

1. 切句；
2. 逐句调用 TTS Provider；
3. 失败重试；
4. 按序号命名；
5. 完整性校验；
6. 返回音频路径列表。

不要让 Agent 对每一句单独调用 TTS，否则容易漏句、乱序、重复扣费，也无法统一做完整性校验。

## 5. 流程

### S1 读取拆分稿

1. 如果 `script` 是文件路径，读取 UTF-8 文本；
2. 去掉首尾空白；
3. 按空行切段（`\n\s*\n`）；
4. 忽略空段；
5. 如果某段仍然包含多个句末标点，继续按 `。！？!?` 切句；
6. `--` / `——` 已由上一个技能处理，这里不再重复处理。

### S2 句子规范化

1. 每句去掉首尾空白；
2. 删除或压缩标点后的连续空格，避免 TTS 读多余停顿；
3. 保留原文标点、数字、英文和专有名词；
4. 不改写句子，不纠正语病；
5. 过滤掉媒体说明行，例如 `[image] 已保存到本地：...`、`[voice] ...`，这些不是口播正文。

### S3 逐句合成

1. 按句子顺序逐句处理，默认串行，保证顺序和限流；
2. 第 `i` 句调用 TTS Provider，生成一个独立音频；
3. 不把多句合并成一个请求；
4. 单句失败重试 `retry` 次；
5. 重试仍失败时停止，并明确报告“第 i 句失败”，不要跳过该句继续后面的句子。

### S4 命名与保存

1. 第 `i` 句保存为 `{i}.{fmt}`；
2. 例如 `1.mp3`、`2.mp3`、`3.mp3`；
3. 写入 `output/sucai`；
4. 目录不存在时由执行脚本创建（具体创建/清理逻辑待后续调整）；
5. 同名文件默认覆盖，具体清理策略后续再定。

### S5 完整性校验

全部句子处理完后，必须检查：

- 句子数 == 音频文件数；
- 文件序号从 `1` 到 `N` 连续，无跳号；
- 每个文件存在且大小大于 0；
- 每个音频可正常读取，时长大于 0（如果 Provider 返回时长则一并校验）；
- 第 `i` 个文件对应第 `i` 句。

任一项不通过，返回失败结果，不宣称“全部完成”。

### S6 返回结果

返回给 Agent：

- 输出目录；
- 句子数；
- 成功生成的音频数；
- 失败句号（如果有）；
- 音频路径列表，按序号排列。

如果需要把音频发给用户，再交给 `send_feishu_file`；不要把音频二进制塞进聊天文本。

## 6. 失败与边界

| 情况 | 处理 |
|---|---|
| 空稿 | 直接报错，不生成文件 |
| 某句为空 | 跳过空句，但不改变其余句子的序号；最终以清洗后的句子列表为准 |
| 单句超长 | 初版直接交给 Provider；若 Provider 限制长度，先报错并指出句号，等待后续支持二次切分 |
| 某句 TTS 失败 | 重试后仍失败 → 停止，报告第几句，不跳过 |
| 部分成功 | 不返回“完成”；明确列出缺失句号 |
| 目录不存在 | 执行脚本创建；创建逻辑后续调整 |
| 旧文件残留 | 初版允许覆盖同名文件；是否清空旧片段后续再定 |
| 重复句 | 不合并，仍然逐句生成对应音频 |
| 中英混排 | 保留原文，交给 TTS Provider 处理 |

## 7. 示例

输入（上一个技能的拆分稿）：

```text
大家好，    欢迎来到我的频道。

今天聊一个很多人关心的问题

为什么你拍的视频没人看？

先说结论，    问题不在设备，    而在开头。
```

输出：

```text
output/sucai/1.mp3
output/sucai/2.mp3
output/sucai/3.mp3
output/sucai/4.mp3
```

对应关系：

```text
1.mp3 ↔ 大家好，欢迎来到我的频道。
2.mp3 ↔ 今天聊一个很多人关心的问题
3.mp3 ↔ 为什么你拍的视频没人看？
4.mp3 ↔ 先说结论，问题不在设备，而在开头。
```

## 8. 验收清单

- [ ] 音频数量等于清洗后的句子数量；
- [ ] 文件从 `1` 到 `N` 连续命名，无跳号、无重复；
- [ ] 第 `N` 个文件对应第 `N` 句；
- [ ] 每个音频文件非空、可播放、时长大于 0；
- [ ] 所有句子都已完成 TTS，没有跳过；
- [ ] 失败时明确报告失败句号，不返回“全部完成”；
- [ ] 输出统一在 `output/sucai`，格式一致。
